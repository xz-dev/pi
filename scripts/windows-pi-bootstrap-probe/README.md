# Actual Pi Windows bootstrap slice

Runs the real `packages/coding-agent/src/cli-bootstrap.ts`, native parent/FILETIME
consumer and single lifecycle worker with Node22.22.2/Bun1.4.4 on native Windows
x64/arm64. It compiles the existing Windows platform addon from its C sources and
uses Pi's single source-Cargo builder for the still-authenticated v0.3.1 pin.
No early production pin update, copied bootstrap, paid model or fake native
identity is used.

Cases: default outer re-exec runs the application once; valid READY consumes
and clears all claim metadata; native parent creation time remains a full16-digit
FILETIME; healthy operation outlives seven seconds; wrong owner and a one-bit
mutation of a real native creation token fail closed; native-owner death closes
the real primary's inherited output; inherited environment opt-out bypasses the
whole ownership bootstrap. The production native read rejects inheritable pipe
handles. The fixture's10s case guard does not change the production2s startup,
5s main/7s worker loss budgets or any native/VM deadline. Guard/rescue fails.

A diagnostic scratch carrier may contain the exact genuinely replayed product
tree solely to let Actions test local owning history. It is never a production
predecessor, a product-branch push or a repair to main. The persistent ci branch
contains only this workflow/fixture. Freeze all tracked source except the two
owned Windows prebuild outputs, then bind their actual compiled bytes separately.

`tasks.mjs` adds actual `execCommand`, built-in local bash operations and the
production owned-spawn adapter under a default-on, validated session owner.
It compares ordinary argv/cwd/env/I/O and7/256/high-u32/max-u32 results against
the same direct launch, while independently retaining full native X in confirmed
completion. Existing native retained-task fixtures acknowledge work1600ms after
primary return, then complete naturally or are canceled through the real adapter.
Confirmed completion requires the production ordered S/X/same-scope C, EOF and
actual child close; the probe does not replace that parser.

Tasks use the existing `PI_PROCWARD_BIN` development override for a separately
source-built exact native6ee candidate. Its canonical native builder, complete
before/after source map and output hashes are retained. This does not update
Pi's authenticated production v0.3.1 source pin, vendor content or versions; that
must wait for formal native release/authenticity verification. Library exports
are built normally after data-only model hydration; no model/provider is called.
The Bun public-status boundary is checked against actual direct behavior, not
inferred permanently from one high-code sample or applied to native wire data.

This is actual Pi source bootstrap/task acceptance, not full installed CLI/TUI,
SDK/MCP, owner-loss hook opportunity or release acceptance. Windows Job owner
death can preempt JavaScript callbacks. Final authenticated source pin and
installed production artifacts still need their own unchanged strict gates.
